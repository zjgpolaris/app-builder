# Design

## Context

项目目前只有 OpenSpec 配置和开发约定。参考 Atoms 的项目对话和 App 预览流程，第一版保留自然语言入口、可见的生成状态、成功后自动出现的交互预览。参考资料包括 [Atoms 产品流程](https://atoms.dev/usecases) 和 [App 预览说明](https://help.atoms.dev/zh/articles/12129554-app-viewer)。

## Goals / Non-Goals

**Goals**

- 一次部署即可通过同源地址访问工作台和生成接口。
- 模型输出可以直接进入隔离预览，成功结果可以从浏览器恢复。
- 通过两条不同需求验证功能确实由模型生成。

**Non-Goals**

- 多智能体分工、容器构建、多文件工程、独立应用发布和跨设备项目同步。
- 保存生成应用内部运行时数据。例如刷新会重启待办应用，之前在预览里添加的任务无需恢复。持久化对象是工作台项目。

## Decisions

1. **工作台使用 React、TypeScript 和 Vite。** 桌面端并排显示需求与结果，窄屏纵向布局。使用清楚的等待、成功、失败和保存状态。采用 Vercel 的同源 Node.js Function 提供 `POST /api/generate`，避免维护独立的常驻服务。 [Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite)
2. **通过 OpenAI Responses API 生成单页应用。** 初始模型选 `gpt-5-mini`，由 `OPENAI_MODEL` 覆盖，服务端读取 `OPENAI_API_KEY`。接口接收 `{ prompt }`，成功时返回 `{ title, html, css, js }`，失败时返回稳定的错误码和简短提示。服务端校验输入、模型响应字段和长度，限制输出大小及单次调用时间，并区分空输入、超时、限流和不可用结果。 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)
3. **预览采用独立的 sandbox iframe。** 工作台生成受控的 `srcdoc` 文档，允许脚本执行，省略 `allow-same-origin`、表单提交、弹窗和顶层导航权限。预览的 CSP 限制外部资源和 API 请求。生成内容只进入 iframe，模型密钥留在服务端。多文件项目需要单独处理依赖、构建和运行隔离，适合后续扩展。
4. **最近成功项目写入同源 localStorage。** 以单条版本化记录保存原始需求、生成结果和保存时间，成功后整体替换。启动时校验记录，损坏时安全回到空白工作台。改用服务端数据库可以支持跨设备访问，也需要项目标识、访问控制和清理策略。
5. **生成状态和最近成功结果分别管理。** 新请求开始时保留已有预览。请求成功后更新预览并尝试保存，失败时保留输入和旧预览。用户可以在重试前修改需求。
6. **内置示例仅切换预览。** 示例使用同一隔离机制，来源明确标注，并可随时返回已生成的项目。示例操作不更新需求、生成结果或持久化记录。

## Risks / Trade-offs

- 模型可能超时或返回不可运行的代码。将接口超时留在部署函数时限之内，校验输出结构，并通过待办、记账两条真实生成用例验证功能。预览运行错误需有明确提示。
- 免登录地址可能消耗模型额度。上线前设置服务端请求限额和模型项目用量告警，达到限额时向用户解释并提示稍后重试。
- 浏览器数据受站点和浏览器配置约束。界面说明保存范围，存储失败时保留当次预览并提示恢复不可用。
